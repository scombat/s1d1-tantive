# Deploy s1d1-tantive on Google Cloud Run

This page shows how to deploy s1d1-tantive on Google Cloud Run with the Cloud Run Button. The button clones this
repository in Cloud Shell, builds `deploy/gcp/Dockerfile` (a single `FROM ghcr.io/scombat/s1d1-tantive:0.8.0-small-onnx-int8`:
Cloud Run cannot pull from GHCR, so the build copies the published image into your project), pushes it to your
registry and runs `gcloud run deploy`. `deploy/gcp/app.json` prompts for the settings.

[![Run on Google Cloud](https://deploy.cloud.run/button.svg)](https://deploy.cloud.run/?git_repo=https://github.com/scombat/s1d1-tantive&dir=deploy/gcp)

The button needs the repository to be public, because Cloud Shell clones it. It carries `dir=deploy/gcp` so that the
root `app.json` stays Heroku's (Heroku requires its file at the root). Checked 2026-10-21 on the Cloud Run Button
source and Google Cloud's memory-limits and pricing pages.

## Facts

- Image: `ghcr.io/scombat/s1d1-tantive:0.8.0-small-onnx-int8`
- RAM: 2048 MiB (`options.memory`, with 1 vCPU)
- Status: needs public repository
- Still to do (you): make the repository public; the images are already public.

## Free tier and variant

Cloud Run's monthly free tier on request-based billing (pricing page, 2026-10-21): the first **180,000 vCPU-seconds**,
the first **360,000 GiB-seconds** and **2 million requests**, in the eligible regions (the page bases it on
us-central1 pricing). The service scales to zero between requests, so a test deployment mostly costs nothing. With
1 vCPU and 2 GiB, the 360,000 GiB-seconds are about 50 hours of active instance time a month. The button uses the
**small** variant (1 GiB needed, 2 GiB given for headroom). For `full` (2 GiB needed) change the tag in the
`Dockerfile` and set `memory` to `4Gi` with `cpu` `2` in `app.json` (2 vCPU accepts up to 8 GiB).

## Variables to set

- `S1D1_TIERS` is required with no default: give the tier names your gateway sends, otherwise the service answers 422.
- `S1D1_API_KEY` is generated by the button (`generator: secret`). It is stored as a plain environment variable of
  the Cloud Run service, readable by anyone who can view the service. Move it to Secret Manager after the first
  deploy (read the generated value from the service's *Variables & Secrets* tab, then):

  ```bash
  REGION=us-central1; SECRET=s1d1-api-key; PROJECT=$(gcloud config get-value project)
  printf '%s' "<the generated key>" | gcloud secrets create $SECRET --data-file=-
  gcloud secrets add-iam-policy-binding $SECRET --role roles/secretmanager.secretAccessor \
    --member "serviceAccount:$(gcloud projects describe $PROJECT --format='value(projectNumber)')-compute@developer.gserviceaccount.com"
  gcloud run services update s1d1-tantive --region $REGION \
    --remove-env-vars S1D1_API_KEY --update-secrets S1D1_API_KEY=$SECRET:1
  ```

  The member above is Cloud Run's default service identity; use yours if the service runs as another account.
- `OTEL_EXPORTER_OTLP_ENDPOINT` is optional: leave it empty for no telemetry export.
- `allow-unauthenticated` is **false**: callers need an identity token (`gcloud auth print-identity-token`) or a
  service account with `roles/run.invoker`. For a gateway outside Google Cloud, either call it with an identity
  token or allow unauthenticated access and rely on `S1D1_API_KEY`:
  `gcloud run services update s1d1-tantive --allow-unauthenticated`.
- Port 8788 is passed to Cloud Run (`options.port`). No health-check path is set: the service loads the model before
  it listens, so Cloud Run's default TCP startup check passes only once it is ready.
- Concurrency 8 and at most 3 instances (the service serialises inference; more instances add capacity).

## Deploy by hand

Cloud Run pulls only from Google's registries, so copy the image into your Artifact Registry first:

```bash
REGION=us-central1; PROJECT=$(gcloud config get-value project)
gcloud artifacts repositories create s1d1 --repository-format=docker --location=$REGION
gcloud auth configure-docker $REGION-docker.pkg.dev
docker pull --platform linux/amd64 ghcr.io/scombat/s1d1-tantive:0.8.0-small-onnx-int8
docker tag ghcr.io/scombat/s1d1-tantive:0.8.0-small-onnx-int8 $REGION-docker.pkg.dev/$PROJECT/s1d1/s1d1-tantive:0.8.0-small
docker push $REGION-docker.pkg.dev/$PROJECT/s1d1/s1d1-tantive:0.8.0-small
gcloud run deploy s1d1-tantive --image $REGION-docker.pkg.dev/$PROJECT/s1d1/s1d1-tantive:0.8.0-small \
  --region $REGION --port 8788 --memory 2Gi --cpu 1 --concurrency 8 --max-instances 3 --no-allow-unauthenticated \
  --set-env-vars "^@^S1D1_TIERS=TRIVIAL=0.15,LOW=0.4,MEDIUM=0.7,HIGH=0.9,EXPERT=1.0@S1D1_FORMATS=systemone,decisions,classify"
```

The values contain commas, so the `^@^` prefix makes `@` the separator between variables (gcloud's alternate delimiter
syntax for list flags).

## Terraform

One file, `deploy/gcp/terraform/main.tf` (provider `hashicorp/google`): the Cloud Run service, its service account and the
Secret Manager key. `image` has no default: copy the published image into your Artifact Registry first (Cloud Run cannot
pull from GHCR). Not applied here (no Google Cloud access).

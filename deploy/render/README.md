# Deploy s1d1-tantive on Render

This page shows how to deploy s1d1-tantive on Render with the Deploy button. `render.yaml` at the root of the
repository is a Blueprint with one web service that pulls the published image (`runtime: image`); nothing is built on
Render.

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/scombat/s1d1-tantive)

The button reads the Blueprint from the repository, so it needs the repository to be public (Render can read a private
one if its GitHub app is installed on it). Checked on render.com/docs on 2026-10-21.

## Facts

- Image: `ghcr.io/scombat/s1d1-tantive:0.6.0-tiny-onnx-int8`
- RAM: 512 MiB (Free plan, checked 2026-10-21)
- Status: needs public repository
- Still to do (you): make the repository public; nothing else is needed, the images are already public.

## Free tier and variant

Render's Free web service has **0.1 CPU and 512 MB of RAM** (compute-plans, 2026-10-21), sleeps after 15 minutes
without traffic and takes about a minute to wake, gets 750 instance hours a month, and has an ephemeral disk
(free page). The `tiny` variant is the only one that fits, and it is tight: it uses about 450 MiB once loaded
(measured locally on the 0.4.0 image, identical service in 0.6.0), so the margin is small and 0.1 CPU makes it slow. The docs say nothing that
forbids an image-backed service on the Free plan, but the first deployment is the real test. To run `small` (1 GiB)
or `full` (2 GiB) choose the `1c-2g` plan (1 CPU, 2 GB) and change the image tag and `plan` together:

```yaml
    image:
      url: ghcr.io/scombat/s1d1-tantive:0.6.0-small-onnx-int8
    plan: 1c-2g
```

## Variables to set

- `S1D1_TIERS` (`sync: false`): Render prompts for it at creation; give the tier set your gateway sends, for example
  `TRIVIAL=0.15,LOW=0.4,MEDIUM=0.7,HIGH=0.9,EXPERT=1.0`, otherwise the service answers 422 to unknown tier names.
- `S1D1_API_KEY` is generated by Render (a random 256-bit value, `generateValue: true`) because a web service has a
  public `onrender.com` URL. Read it in the service's Environment tab and use it as `Authorization: Bearer <key>`.
- `PORT=8788`, `S1D1_FORMATS`, `S1D1_DEADLINE_MS` are set; the health check is `/ready`, so traffic switches to a new
  deploy only once the model has loaded.
- `autoDeployTrigger: "off"`: a push to the repository does not redeploy copies created with the button (the
  Render docs recommend this for button Blueprints).

## Deploy by hand

New → Web Service → Existing Image → `ghcr.io/scombat/s1d1-tantive:0.6.0-tiny-onnx-int8`, instance type Free,
Advanced → Health Check Path `/ready`, and the environment variables above.

## Terraform

One file, `deploy/render/terraform/main.tf` (provider `render-oss/render`): the web service on the published image,
`/ready` health check and a generated key. Set `RENDER_API_KEY` and `RENDER_OWNER_ID`. Not applied here (no Render account).
